# Дорожная карта: замечания и новые фичи

**Дата составления:** 2026-07-29
**Статус:** согласовывается

План по итогам разбора семи замечаний. Связки:
- «О приложении» (п.5) — место активации dev-режима (п.6);
- экспорт/импорт (п.7) и шеринг (п.4) делят один механизм кодирования подборок;
- все новые фичи (п.2, п.4, аккорды) гейтятся за dev-режимом.

---

## Исходные замечания

1. Долго открывается попап поиска при клике по номеру песни на странице песни.
2. Страница списка песен с сортировкой по номеру / по алфавиту / группировкой по разделам.
3. Не работает поворот на бок в установленном PWA.
4. Делиться подборками через ссылку.
5. Страница инструкции.
6. Режим разработчика для доступа к экспериментальному функционалу.
7. Случай, когда пропали не пустые подборки.

---

## Решения по пунктам

### 1. Попап поиска — синглтон индекса

**Причина:** попап обёрнут в `v-if` + `<Transition>`, внутри `<SongSearchInput>`, который при каждом открытии монтируется заново и в `onMounted` строит индекс Lunr + exact-индекс по 1565 песен (`composables/useSongSearch.js:10`, `components/SongSearchInput.vue:65`). На главной индекс строится один раз — поэтому там быстро.

**Решение:** вынести state `useSongSearch` на уровень модуля (синглтон); `buildIndex` — no-op, если индекс уже построен. Строить один раз за сессию при первом доступе к `allSongs`. Попап на странице песни открывается мгновенно.

**Уточнено:** лаг при каждом открытии → синглтон полностью решает.

### 2. Страница списка песен

Новой страницы нет; данные есть — `songs.json` содержит `sections` (54 раздела с `song_ns`) и `title` у каждой песни.

**Решение:** маршрут `/songs` с тремя режимами:
- **По номеру** — плоский список 1…1565.
- **По алфавиту** — группировка по первой букве названия. Латиницы/цифр сейчас нет, но группу «#» держим на будущее.
- **По разделам** — группы по `sections[].title` + песни из `song_ns`.

Производительность: 1565 элементов → сворачиваемые секции (по умолчанию свёрнуты, кроме первой). Варианты (а/б) не показываем. В список встроить кнопку-иконку открытия попапа с `SongSearchInput` (как на странице песни) — переиспользуем синглтон-индекс из п.1. Поиск остаётся и на главной.

**Уточнено:**
- Вход — «Все песни» в боковом меню (только при `devMode`).
- Варианты в списке пока не отображаем.

### 3. Поворот на бок

**Причина:** в манифесте PWA `orientation: 'portrait'` (`nuxt.config.js:40`) — блокирует ландшафт в установленном PWA. В браузере поворот работает (манифест не влияет).

**Решение:** `orientation: 'portrait'` → `'any'`. После — обязательная визуальная проверка ландшафта через Playwright-скриншот (по правилам редизайна): узкая колонка текста, навбар.

**Уточнено:** баг именно в установленном PWA; вёрстку в ландшафте ещё не проверяли (не поворачивалось).

### 4. Шеринг подборок через ссылку

Подборки локальны в IndexedDB с autoIncrement `id` — расшарить `id` бессмысленно. Но база песен общая (один `songs.json`), поэтому подборка = `{name, [(songNumber, variantIndex), …]}`.

**Версионирование:** добавить поле `version` (целое, монотонное) в `songs.json` (`scripts/parseTxt.js`); сохранять `songsVersion` в настройках при `fetchSongs`. В payload шеринга класть `v` = версия базы у того, кто делится.

Логика при импорте у получателя:

| У получателя версия | Действие |
|---|---|
| **Меньше**, чем в payload | База устарела → «Обновите базу данных» + кнопка; после обновления повторить импорт. |
| **Больше или равна** | Импорт. Валидация: песня не найдена → пропустить с предупреждением; `variantIndex` вне диапазона вариантов → прижать к 0 с пометкой. |

Случай «у того, кто делится, база ниже, чем у получателя» — безопасен: подборка ссылается только на номера + индексы вариантов, а не на контент; номера стабильны. Риск — изменившиеся варианты → падаем на variant 0 с мягким предупреждением «подборка из более старой версии базы, проверьте варианты».

**Решение:**
- Общий модуль кодирования подборки → строка (JSON → LZ-string → base64url). Переиспользуется в экспорте (п.7).
- Кнопка «Поделиться» на странице подборки: `navigator.share` + копирование ссылки. Payload: `{name, v, items:[[songNumber, variantIndex],…]}`. Только обычные подборки.
- Маршрут `/collections/import#<data>` (fragment — не уходит на сервер, нет лимита длины): просмотр (read-only) + «Сохранить в мои подборки» с предложением слить с существующей по имени.

**Уточнено:**
- Делиться только обычными подборками («Избранное» — нет).
- При импорте — предлагать слить с существующей по имени.
- Версионирование — как выше.

### 5. Страница инструкции + «О приложении» (объединяем)

Маршрут `/about`. Короткая шпаргалка по экранам + блок «О приложении» (версия/коммит/дата сборки из `appConfig`: `appVersion`, `appCommit`, `appBuildDate`). Вход — из бокового меню внизу, рядом с «Настройки».

На этой же странице — блок диагностики (см. п.7) и активация dev-режима (см. п.6).

### 6. Режим разработчика

Поле `settings.devMode` (boolean, персистентно). Активация — 7 тапов по версии приложения на странице «О приложении» (Android-style, не маячит обычным пользователям). В `settings.vue` появляется секция «Экспериментальные функции» при `devMode=true`.

**Гейтить за dev-режимом:** все новые фичи (список песен п.2, шеринг п.4) + скрытые сейчас (аккорды). «О приложении», поворот, синглтон поиска, сохранность данных — общедоступны.

**Уточнено:**
- Активация тапом по версии на странице «О приложении».
- Все новые фичи проводим через dev-режим.

### 7. Потеря подборок — сохранность данных

**Симптомы:** пропали сами записи коллекций (с названиями), часть осталась, базу не обновляли, кэш не чистили, доступа к устройству нет.

**Что не подходит:** миграции не удаляют записи из `collections` (только `songCollections.clear()` в v2→v3/v3→v4) → не объясняют потерю имён; `deleteCollection` требует подтверждения на каждую → случайно потерять «часть» малореально.

**Наиболее вероятная причина:** eviction хранилища браузером. IndexedDB без `navigator.storage.persist()` помечен как best-effort — браузер/ОС могут освободить его при нехватке места; на Android известны случаи частичной потери. В коде `navigator.storage.persist()` не вызывается. Доп. фактор — хрупкие миграции (clear-then-put с уникальным индексом) могли добить связи при прошлом апдейте, но не имена.

**Вывод:** без устройства точную причину не установить → работаем на профилактику + диагностику.

**А. Профилактика:**
1. `navigator.storage.persist()` при первом взаимодействии.
2. Авто-бэкап подборок в localStorage при каждом изменении (данные крошечные: имена + связи).
3. Ручной экспорт/импорт JSON в настройках (+ «восстановить из бэкапа», если при старте коллекции пусты, а в localStorage есть бэкап). Переиспользует кодирование из п.4.
4. Харденинг миграций: убрать `clear()` перед повторным `put`, перейти на upsert через курсор.

**Б. Диагностика на будущее** (доступа к DevTools нет):
5. На странице «О приложении» — блок диагностики: «Подборок: N, Связей: M, Песен: K, Версия БД: V, Persistent: да/нет».

**Уточнено:**
- Пропали сами подборки (с названиями), часть осталась.
- Базу не обновляли, кэш не чистили.
- Доступа к устройству нет — точно причину назвать нельзя.

## Фазы и порядок работ

```
Фаза 0 (dev-режим + /about) ──► Фаза 3, 4, 5 (всё за dev-режимом)
Фаза 1 (независимо)
Фаза 2 (независимо; 2.5 ждёт 0.2)
Фаза 4 переиспользует кодирование из 2.3
```

### Фаза 0 — Фундамент
- **0.1.** Dev-режим: `settings.devMode`, активация 7 тапов по версии на `/about`, секция «Экспериментальные функции» в `settings.vue`.
- **0.2.** Страница `/about`: шпаргалка + блок «О приложении» + блок диагностики (п.7.Б, зависит от 2.5).

### Фаза 1 — Быстрые победы
- **1.1.** Синглтон поискового индекса (п.1).
- **1.2.** Поворот: `orientation: 'any'` + визуальная проверка ландшафта (п.3).

### Фаза 2 — Сохранность данных (п.7)
- **2.1.** `navigator.storage.persist()`.
- **2.2.** Авто-бэкап подборок в localStorage.
- **2.3.** Ручной экспорт/импорт JSON в настройках.
- **2.4.** Харденинг миграций (upsert без `clear`).
- **2.5.** Блок диагностики на `/about` (зависит от 0.2).

### Фаза 3 — Список песен (п.2), за dev-режимом
- **3.1.** Маршрут `/songs`: по номеру / по алфавиту / по разделам.
- **3.2.** Сворачиваемые секции; варианты не показываем.
- **3.3.** Кнопка попапа поиска в списке (переиспользует синглтон из 1.1).
- **3.4.** Вход «Все песни» в боковом меню при `devMode`.

### Фаза 4 — Шеринг подборок (п.4), за dev-режимом
- **4.1.** `version` в `songs.json` + `songsVersion` в настройках.
- **4.2.** Общий модуль кодирования подборки (переиспользуется в 2.3).
- **4.3.** Кнопка «Поделиться» на странице подборки (`navigator.share` + копирование ссылки).
- **4.4.** Маршрут `/collections/import#<data>`: просмотр + «Сохранить» с предложением слить по имени; версионирование по таблице выше.

### Фаза 5 — Аккорды
- **5.1.** `showChordsSection` за `devMode` (показывать секцию только в dev-режиме); снять `.skip` в `test/e2e/specs/settings.spec.js`. См. `docs/restore-chords-toggle.md`.
