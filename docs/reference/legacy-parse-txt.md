# Legacy: парсер scripts/parseTxt.js

Справочник по **устаревшему** пайплайну. Актуальный источник данных — `songs-data/songs/*.txt` (см. `song-format.md`); `parseTxt.js` остался для разовой конвертации исходного сплошного файла и запускается вручную через `npm run parse-txt`.

Node.js-скрипт конвертирует `tmp/doc.txt` → `tmp/result.json`.

## Формат tmp/doc.txt

Тексты песен, разделённые заголовками секций.

**Заголовок секции** — строка с заглавной буквы, за которой следует строка с номером песни:
```
Перед началом собрания
1. 1. Слушайте повесть любви...
2. 1. Вот настал молитвы час...
```

**Песня** начинается с паттерна `N. [метка] 1. текст` или `N. [метка] Припев: текст`:
```
1. 1. Слушайте повесть любви в простоте...        — обычная песня
235. (а) 1. Со Христом бодрее в путь пойду...      — песня с вариантом (а)
1254. (вариант для сестёр) 1. Хотела б я...        — описательная метка
```

**Куплеты** начинаются с `N.`, **припевы** — со слова `Припев:` или `Припев.`.

**Варианты** обозначаются меткой `(метка)` в начале строки (или после пустой), за которой следует номер куплета или Припев. Внутритекстовые скобки (`3(а). текст`, `(Припев 2 вариант: ...)`, `Припев 1:`) границами вариантов **не являются**.

## Алгоритм

1. Загружает красивые названия из `tmp/names.tsv` (формат: `номер\tназвание`)
2. Определяет заголовки разделов
3. Извлекает песни по паттерну `N. [(метка)] 1. текст`
4. `splitVariants()` — делит контент на варианты по меткам
5. `parseSongBody()` — парсит тело варианта: куплеты по `N.`, припевы по `Припев:`; многострочные части объединяются через `\n`
6. `check()` верифицирует, что `song.n - song.id === 1` для всех песен и что каждая песня имеет хотя бы один вариант с непустым body

## Выходной формат

```json
{
  "songs": [
    { "id": 0, "n": 1, "title": "...", "variants": [{ "label": "", "body": [...] }] },
    { "id": 234, "n": 235, "title": "...", "variants": [{ "label": "а", "body": [...] }, { "label": "б", "body": [...] }] }
  ],
  "sections": [{ "id": 0, "title": "...", "song_ns": [1, 2, 3] }]
}
```

## Переход на songs-data/

`songs-data/convert.js` выполняет обратную операцию — разбирает готовый `songs.json` на отдельные `songs/NNNN.txt` + `sections.json`. Именно так одноразово получился текущий набор исходников; после этого `parseTxt.js` в регулярном цикле не участвует.
