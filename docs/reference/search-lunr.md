# Поиск: настройка и изыскания по Lunr.js

Справочник. Нужен, когда меняется ранжирование поиска или разбирается жалоба «песня не находится». Основной код — `lib/search.js`, тесты — `lib/search.test.js`.

## API lib/search.js

Чистые функции без Vue-зависимостей.

- `stripRemarks(text)` — убирает ремарки исполнителю `[…]` **вместе с содержимым**, заменяя на пробел. Ремарка не поётся, а слова в ней обычные («припев», «куплет», «петь»), поэтому в индексе она давала выдачу, выглядящую осмысленной: запрос «куплет» находил ровно те четыре песни, где ремарка есть (`0662`, `0902`, `0928`, `1158`). На экране ремарка остаётся — чистка только на входе в индекс
- `cleanText(text)` — вызывает `stripRemarks`, затем удаляет спецсимволы ``/[]()!?.,;:"'-`` и схлопывает пробелы. Круглые скобки только снимаются: внутри них слова песни (подголоски)
- `prepareSongForIndexing(song)` — `{ n, title, content }`; контент всех вариантов объединяется. Поддерживает старый формат с `body` на верхнем уровне
- `prepareVariantsForIndexing(song)` — каждый вариант отдельно: `{ ref, n, title, content, variantIndex }`, ref формата `"number:variantIndex"`
- `buildSearchIndex(songs)` — индекс Lunr с русским стеммингом (`this.use(lunr.ru)`); `title`: boost 10, `content`: boost 1
- `performSearch(searchIndex, query, limit=0)` — поиск с нечётким совпадением, минимальная длина запроса 3 символа, `limit=0` — без лимита
- `parseSearchRef(ref)` — разбирает составной ref `"number:variantIndex"`

## Индексация

- Стоп-слов фильтр **отключён** (`this.pipeline.remove(lunr.stopWordFilter)`) — это позволяет искать по предлогам и местоимениям («как», «я», «в», «со»), которые являются важными словами в названиях гимнов. Но это создаёт шум: частые слова встречаются в сотнях документов, имеют низкий IDF и ухудшают ранжирование.
- Title boost = 10 даёт значительное преимущество совпадениям в заголовке. Boost 3 был недостаточен; boost 20 разделяет ещё лучше, но 10 — приемлемый баланс.
- Русский стеммер Lunr (`lunr.ru`) работает агрессивно: «улететь» → «улетет», «хочу» → «хоч», «небеса» → «небес».

## Стратегия поискового запроса (performSearch)

- Все слова кроме последнего помечаются `+` (обязательное вхождение): `+хочу +улететь`
- Последнее слово получает fuzzy `~2` (2 правки по Левенштейну): `улет~2`
- Итоговый запрос: `+как +я +хочу улет~2`
- **Fallback:** если `+`-запрос даёт 0 результатов, выполняется запрос без `+`

Fuzzy `~2` необходим, потому что стеммер обрезает окончания по-разному для полных и неполных слов: «улететь» → «улетет», но «улет» → «улет» — расстояние Левенштейна между стеммами = 2. `~1` было недостаточно.

## Ограничения Lunr (bag-of-words)

- Порядок слов и близость не учитываются: «как я хочу» и «хочу я как» дают одинаковый результат
- Фразовый поиск (`"как я хочу"`) несовместим с fuzzy-оператором
- Стоп-слова после стемминга совпадают с огромным числом документов, их IDF ≈ 0 — на ранжирование они почти не влияют
- `+как` в сочетании с другими `+`-термами может давать 0 результатов, потому что пересечение слишком узкое — отсюда необходимость fallback
- При запросе «как хоч» песня «Как я хочу улететь в Небеса» (#1554) не найдётся: у «как» слишком низкий IDF. Но «хочу улет» находит #1554 на первом месте благодаря `+хочу +улет~2`
