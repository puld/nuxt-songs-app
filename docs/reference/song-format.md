# Формат исходников песен (songs-data/)

Справочник. Нужен при правке текстов песен, парсера `songs-data/parse.js` или линтера `songs-data/lint.js`.

## Файл песни: songs-data/songs/NNNN.txt

1565 файлов вида `0001.txt`, `0235.txt` (номер с ведущими нулями до 4 знаков).

```
#1 Слушайте повесть любви в простоте

1. Слушайте повесть любви в простоте,
Слушайте дивный рассказ:
Бог нас навеки простил во Христе,
Бог нас от гибели спас.

Припев:
Бог нас от гибели спас!
Да! Бог нас навеки простил во Христе,

2. Если неправда потерянных дней
Мучит вас в тягостный час,

@meta
meter: 4-стопный хорей
rhyme: ABAB
@end
```

- **Первая строка** — заголовок `#<номер> <название>`. Без него `parseSongFile()` бросает ошибку.
- **Куплеты** начинаются с `N.` (номер + точка), **припевы** — со слова `Припев:` или `Припев.`
- Строки внутри части объединяются через `\n` — стихотворная разбивка сохраняется
- **Блок `@meta ... @end`** — метаданные о размере и рифме; вырезается парсером и в `songs.json` не попадает. Есть во всех 1565 файлах

## Варианты песни

Метка в круглых скобках в начале строки (или после пустой), за которой следует номер куплета или Припев:

```
(а)
1. Со Христом бодрее в путь пойду я,
...
(б)
1. ...
```

Метки бывают буквенные (`(а)`, `(б)`) и описательные (`(вариант для сестёр)`).

`splitVariants()` разделяет **только** такие метки. Не являются границами вариантов:
- `3(а). текст` — нумерация куплета внутри текста
- `(Припев 2 вариант: текст)` — альтернативный припев внутри текста
- `Припев 1:` / `Припев 2:` — нумерованные припевы внутри текста

Песен с несколькими вариантами: 9 (номера 235, 854, 1067, 1175, 1188, 1254, 1309, 1363, 1455).

## Разделы: songs-data/sections.json

```json
[{ "title": "Перед началом собрания", "song_ns": [1, 2, 3] }]
```

Разделы — часть базы песен, а не отдельная навигационная прихоть: по ним группируется страница «Все песни». Целостность проверяет `checkSectionsIntegrity` (`songs-data/sections-integrity.js`), и её зовут оба инструмента — `parse.js` при сборке и `lint.js` при полном прогоне, то есть в CI-job'е, обязательном для мержа в `main`. Ошибками считаются четыре случая: значение в `song_ns` не номер; номер, которому не соответствует песня; песня в двух разделах; песня вне всех разделов.

**Добавление или удаление песни — работа в двух файлах, а не в одном.** Порядок:

1. Создать (удалить) `songs-data/songs/NNNN.txt`.
2. **Сразу** вписать номер в `song_ns` нужного раздела `sections.json` (или убрать оттуда).
3. `npm run songs:lint` — формат `.txt` плюс согласованность разделов.

Без шага 2 красные и линтер, и сборка: `npm run dev` / `build` / `generate` останавливаются на `songs:parse` до запуска Nuxt. Это сделано намеренно — раньше расхождение проходило молча, и песня вне разделов уезжала в группу «Вне разделов», где её никто не ищет. Правка одного `sections.json` тоже проверяется: pre-commit гоняет проверку разделов, когда этот файл в индексе.

## Аккорды

- `{Am}` — аккорд над строкой (надпись `chord-label`)
- `{_G}` — инлайн-аккорд в строке текста (`chord`)
- `{2:Dm}` — аккорд только второго прохода повтора (см. ниже)

Разметку строит `lib/chordMarkup.js` (`renderChords`), раскладку столкнувшихся
надписей — `lib/chordLayout.js`. При выключенных аккордах `{…}` вырезаются
целиком. Надпись над строкой выведена из потока, поэтому текст верстается ровно
так же, как без аккордов.

### Аккорды разных проходов повтора

У Эппа второй проход репризы часто выписан вольтой со **своей** гармонией:
аккорды стоят на других слогах и в другом количестве, соответствия «аккорд к
аккорду» нет. Поэтому проход помечается **внутри** фигурных скобок, а текст
остаётся единственным:

| Запись | Значение |
|--------|----------|
| `{G}` | звучит в каждом проходе |
| `{2:Dm}` | только во втором проходе |
| `{1,3:F}` | в первом и третьем |
| `{2:_G}` | то же для инлайнового аккорда — пометка идёт первой, до `_` |

Правила:
- номер относится к **ближайшему охватывающему** повтору `/…/Nр.`;
- аккорд без пометки достаётся каждому проходу — помечать нужно только
  расхождения;
- пометка вне повтора, номер больше счётчика, `{0:F}` и «все проходы разом»
  (`{1,2:F}` внутри `/…/2р.`) — ошибки, их ловит линтер.

Пример:
```
/{G}Твою лю{1:C}бовь про{1:D}славлю {2:Em}я
Во все кон{1:G}цы зем{2:D7}ли.{2:G} /2р.
```

**Повтор с такими аккордами разворачивается при отрисовке**: печатается N копий
текста, каждая со своими аккордами. Маркеры `/` и `/Nр.` при этом не выводятся —
рядом с уже напечатанными копиями они читались бы как ещё один повтор поверх
раскрытого; курсив репризы остаётся, чтобы было видно происхождение строк.
Копии разделяются переносом строки, если фрагмент сам многострочный, и пробелом,
если он часть строки (`/Близок Господь! /2р.` → «Близок Господь! Близок
Господь!»). Повтор без помеченных аккордов показывается по-прежнему — со
слешами и счётчиком.

Дублировать ради разной гармонии сам текст нельзя: одна строфа оказалась бы в
двух местах файла, и опечатку пришлось бы править дважды.

## Повторы (репризы)

Обрабатываются в `lib/repeats.js` (`processRepeats`), тесты — `lib/repeats.test.js`.

| Маркер | Значение |
|--------|----------|
| `/` | Открывающий маркер повтора (один уровень) |
| `/Nр.` | Закрывающий маркер (закрывает один уровень). Варианты: `/2р.`, `/2р`, `/ 2р.`, `/2 р.` |
| `//` | Два открывающих маркера подряд — начала двух вложенных повторов совпадают |

Правила:
- Каждый открывающий `/` имеет парный закрывающий `/Nр.`
- **У каждого закрывающего слеша обязан быть свой счётчик.** Два уровня закрываются раздельно — `/3р. /2р.`, а не `//2р.`: слеш без цифры для парсера означает **открывающий** маркер, поэтому `//2р.` читается как два новых повтора, а не как двойное закрытие
- Слеши повторов и переносы строк **независимы** — повтор может начинаться на одной строке и заканчиваться на другой
- Повторы **НЕ разворачиваются** — только подсветка в UI (`<span class="repeat">`), маркеры остаются видимыми в тексте. Исключение — повтор с аккордами, помеченными проходом (см. «Аккорды разных проходов повтора»)

Баланс маркеров в строфе проверяет линтер (`songs-data/repeat-balance.js`,
правило 10 в `lint.js`). Без этой проверки ошибка разметки не заметна: парсер
несбалансированную строфу не бракует, а отдаёт **сырым текстом** — со слешами и
«2р.» прямо на экране, без ошибки в консоли. Линтер ловит четыре случая:
`//Nр.` (у первого слеша нет счётчика), счётчик без «р» (`/2` вместо `/2р.`),
закрывающий маркер без открывающего и незакрытые открывающие. Маркеры внутри
`@meta` — текст описания, они не проверяются.

Пометки проходов проверяет соседнее правило (`songs-data/chord-passes.js`,
правило 11): номер должен относиться к охватывающему повтору и не превышать его
счётчика.

Следствие синтаксиса: слеш в строфе зарезервирован под репризу, поэтому дробь
или дату (`1/2`) писать нельзя — линтер посчитает такой слеш незакрытым
открывающим.

Простой повтор:
```
/А в Нём земных скорбей забвенье./ 2р.
```

Вложенные повторы:
```
//О Иисус мой! /2р.
За меня Ты Кровь пролил. /2р.
```
Внутренний — `/О Иисус мой! /2р.`, внешний — вся секция. Исполнение:
```
О Иисус мой!
О Иисус мой!
За меня Ты Кровь пролил.
О Иисус мой!
О Иисус мой!
За меня Ты Кровь пролил.
```

Строка после `//текст /Nр.` без `/` в начале — продолжение внешней секции повтора.

Закрытие двух уровней может стоять и на отдельной строке — так записан `0940`:
```
//«Вечная слава! /3р.
/Слава Христу!» /2р.
/2р.
```

## Выходной формат songs.json

```json
{
  "songs": [
    {
      "n": 1,
      "title": "Слушайте повесть любви в простоте",
      "variants": [
        {
          "label": "",
          "body": [
            { "id": 0, "type": "verse", "n": 1, "content": "..." },
            { "id": 1, "type": "chorus", "n": 1, "content": "..." }
          ]
        }
      ]
    }
  ],
  "sections": [{ "id": 0, "title": "...", "song_ns": [1, 2, 3] }]
}
```

`id` частей сквозной в пределах песни — нумерация продолжается между вариантами.
