# Карта «наш номер песни → номер нотного листа Эппа»

Итог — `numbers-final.tsv` (наш номер, лист, как сопоставлено, уверенность) и
`numbers-final.json` (то же плюс файлы листа и служебные поля).

**Сопоставлено 1319 из 1565.** Зона 1–830 — 825 из 830 (номер совпал у 816),
зона 831+ — 494 из 735. Уверенность: высокая 1279, средняя 40.

## Как строится

Три источника, по возрастанию надёжности; каждый следующий перебивает предыдущий.

1. **Номер листа** (`mapnums.py`, `via: номер`) — работает в зоне 1–830, где
   нумерация общая. Номер сам по себе не принимается: заголовок листа должен
   сойтись с нашим текстом, иначе это расхождение, а не совпадение.
2. **Заголовок листа** (`headings.py` → `mapnums.py`, `via: название`) —
   единственная связь выше 830, где у издателя свой сборник по алфавиту первой
   строки. Заголовок берётся **с самого листа**, а не из подписи каталога:
   в каталоге он обрезан.
3. **Текст под нотами** (`syllables.py` → `matchtext.py`, `via: текст`) — самый
   надёжный и последний по времени. Им же проверена вся карта целиком.

## Почему текст важнее заголовка

Эпп подписывает лист **первой пропеваемой строкой**, и не обязательно первого
куплета: строкой припева, раскрытым повтором, с опечатками. Поэтому заголовок
даёт как ложные совпадения (разные песни с одинаковым началом — «О Господь мой!»),
так и ложные расхождения.

Проверка карты текстом (`matchtext.py verify`): **1300 подтверждено, 6 оказались
чужими листами, 4 сняты как ложные, 19 текст не подтвердил** (у части листов под
нотами вовсе нет слов — такие остаются в карте с пометкой «средняя»).

Метод проверен на контрольной выборке уже сопоставленных песен: **124 из 124 при
нуле расхождений** (`tune.py`), и на 16 расхождениях зоны 1–830 он воспроизвёл все
восемь ручных находок и добавил две.

## Устройство сверки по тексту

Слоги под нотами идут вперемежку по голосам и куплетам, поэтому слова
группируются по строке (`round(y0/6)`) и сортируются по x, а затем склеиваются в
**сплошной поток строчных букв без пробелов** — слово разорвано на слоги, и
пробелы только мешают. Наш текст сводится к такому же потоку, режется на зонды по
18 букв встык, и лист принимается при **четырёх совпавших зондах** (72 буквы).

- **Зонд короткий намеренно**: в поток листа вклиниваются подписи автора и
  ремарки («…любить {ккроманов} науч и меня…»), и зонд длиннее почти всегда
  напарывается на вставку. Замер: зонд 30 букв давал 86 из 124 на контроле,
  зонд 18 — 124 из 124.
- **Кандидат — лист, а не файл**: один лист лежит под несколькими именами
  (`1324.pdf` и `1324a.pdf` — та же песня в другой аранжировке).
- **Отрыв от второго кандидата** (`LEAD`) отсеивает разные редакции одной песни:
  наш 211 одинаково ложится на 1005 «Пусть море бурное» и 861 «Вот море бурное».
  Такие уходят в `text-review.tsv`, а решение записывается в `manual.tsv`.
- **Шрифт листа — cp1251, отданный как latin-1**; `fix()` применяется построчно:
  на листе смесь кодировок, и юникодная «Музыка:» роняет всю страницу.

## Расхождения нумерации в зоне 1–830

`numbers-diverged.tsv` — 16 мест, где под нашим номером у издателя лежит другая
песня. Текст указал настоящий лист у десяти: 195→941, 249→2048, 282→1044,
339→2245, 426→1217, 475→2436, 487→487, 495→1164, 711→711, 724→1062.

Два последних — не расхождения вовсе: на листе 487 напечатаны **две** песни, а
711 подписан другим переводом первой строки («О Иегова» вместо «Бог Великий,
через волны»).

## Порядок прогона

```
python fetch.py missing-pdf.txt   # докачать каталог (3293 листа)
python headings.py                # заголовки листов → headings.json
python syllables.py               # текст под нотами → syllables.json
python mapnums.py                 # карта по номеру и заголовку → numbers.json
python matchtext.py check         # контроль метода на известных песнях
python matchtext.py apply         # добить карту текстом → numbers-final.json
python matchtext.py verify        # проверить всю карту текстом
python finish.py                  # правки, ручные решения, снятие ложных
```
