# Приёмка спорных сопоставлений (пункт 9.9)

358 песен, 607 кандидатов. Решение принимает человек: угадывать нельзя — ошибка
привяжет к песне чужие ноты и всплывёт только на экране. Модель здесь не нужна
и вредна, инструмент лишь ставит рядом наш текст и верх нотного листа Эппа.

## Запуск

```
cd notes-omr/pdf-epp
../.venv/bin/python review_make.py     # готовит review-data.json (~19 МБ, минута)
../.venv/bin/python -m http.server 8899 --bind 127.0.0.1
```
Открыть http://127.0.0.1:8899/review.html — `file://` не годится, страница
читает данные через fetch.

## Работа

Слева-сверху наш эталон (название и первые строфы), ниже — кандидаты: превью
верхней трети листа, где напечатаны номер, заголовок и первая система.

- <kbd>1</kbd>…<kbd>9</kbd> — принять этого кандидата
- <kbd>0</kbd> — ни один не подходит (у песни нот нет)
- <kbd>?</kbd> — отложить, вернуться позже
- <kbd>←</kbd> / <kbd>→</kbd> — листать

Решения пишутся в localStorage сразу, поэтому вкладку можно закрыть и вернуться
— страница откроется на первой нерешённой песне. Кнопка «Скачать решения»
отдаёт `decisions.json` вида `{"90": {"file": "090d.pdf", "verdict": "принято"}}`.

## Что дальше с решениями

`decisions.json` применяется к `mapping.json` отдельным шагом (пока не написан):
принятые кандидаты уходят в маппинг, «ни один» — в список песен без нот, который
нормальное состояние данных, а не пробел.

**Варианты нот** (595 номеров с несколькими PDF) идут этим же инструментом:
кандидаты одной песни показаны вместе, и выбор одного из них — это и есть выбор
варианта. Связь с нашими вариантами песни пока не решена.
