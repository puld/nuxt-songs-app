# Ноты из PDF: распознавание, ABC, звучащая страница

Исследование для песенника (`~/workspace/my/nuxt-songs-app`): можно ли получить
из сборника нот машинно-читаемую партитуру и показать её в браузере так, чтобы
она играла. Ответ — да: разобраны все четырнадцать PDF, что были под рукой, и
не только финалевские (шрифт **Maestro**) — Opus, безымянные подмножества
издательских шрифтов и две партитуры, набранные самодельным нотным шрифтом.

Сюда перенесено из временного каталога сессии, чтобы не потерять.

## Что уже сделано

**Четырнадцать песен** разобраны общим конвейером: `out/NNN.abc` — запись нот,
`out/NNN.html` — автономная звучащая страница, `out/index.html` — список всех.
Около 290 тактов, ноль расхождений по всем колонкам приёмки (см. «Пакетный
разбор»), ноль предупреждений abcjs при разборе ABC.

Страница **автономна**: открывается двойным кликом, в сеть не ходит вовсе
(проверено перехватом всех запросов в Playwright), весит ≈ 6 МБ — из них 5.5 МБ
занимают семплы, одинаковые у всех песен.

Что умеет страница: играть партитуру целиком или только мелодию, два тембра
(фортепиано / хор), транспонирование ±5 полутонов кнопками, подсветку звучащих
нот с курсором, автопроход всех куплетов со сменой слов под нотами без
остановки звука, переключение куплета вручную на ходу.

`songs/093/` и `songs/119/` — первые, рукописные конвейеры, оставленные как
есть. У 119 там лежит `119full.html` — **единственная** страница с фортепианной
партией (голоса `P1`–`P3` и своя строка `%%score`); общий конвейер аккомпанемент
не переносит (см. «Находки»), зато проходит общую приёмку.

## Как это работает

Распознавание идёт **не по картинке, а по координатам глифов**: Finale пишет
ноты символами шрифта Maestro из Private Use Area (U+F0CF — закрытая головка,
U+F0FA — открытая, U+F06A/U+F04A — флаги, U+F02E — точка, U+F062/U+F023/U+F06E —
бемоль/диез/бекар, U+F026/U+F03F — ключи). Высота ноты считается от координаты
Y относительно линеек нотоносца, линейки берутся из `page.get_drawings()`.
Поэтому результат точный, а не вероятностный — это разбор вёрстки, не OMR по пикселям.

Конвейер (`pipeline/`, запускать из каталога с PDF, нужен `pymupdf`):

| Шаг | Файл | Что делает |
|-----|------|-----------|
| 1 | `fontmap.py` | опознание нотного шрифта по составу кодов и приведение их к U+F0xx |
| 1 | `omr.py` | нотоносцы, глифы, головки нот, флаги, точки, знаки альтерации |
| 2 | `satb.py` | сборка партитуры: такты, разведение по четырём голосам, паузы |
| 2 | `meta.py` | заголовок, размер, тональность, метроном, характер исполнения |
| 2 | `lyrics.py` | слоги под нотами: куплеты, припев, метки «1-4», «@T» |
| 2 | `slurs.py` | лиги и продления нот |
| 2 | `volta.py` | репризы, вольты, словесные ремарки (`Fine`, `rit.`) |
| 2 | `dynamics.py` | оттенки (`p`, `mp`, `mf`, `f`) с привязкой к стану |
| 2 | `glyphstaff.py` / `glyphtext.py` | партитуры, набранные самодельным нотным шрифтом (664, 974) |
| 3 | `abcout.py` | ABC notation: `%%score {(S A) \| (T B)}`, вязки, `w:` по куплетам |
| 4 | `mkhtml.py` | автономная HTML: abcjs + ABC + mp3-семплы в base64 |
| — | `barnums.py` | сверка с номерами тактов, напечатанными в PDF |
| — | `checkall.py` | регрессионная сетка по всем PDF разом |

Прежние `score.py` / `abcgen.py` — первая версия конвейера, оставлена для 093.
Запускать из `pipeline/`: `python3 abcout.py ../pdf/752.pdf`, затем
`python3 mkhtml.py ../out/752.abc ../out/752.json ../out/752.html`.

`assets/` — то, что вшивается в страницу: `abcjs-basic-min.js` (500 КБ),
`abcjs-audio.css` (панель плеера), `sf/` — семплы FluidR3_GM, по 46 нот C2..A5
на тембр, 25.6 КБ на ноту.

## Грабли, на которые уже наступили

- **`setTune` не пересобирает звук.** `runWhenReady` в abcjs зовёт `go()` только
  при `!isLoaded`, а ни `setTune`, ни `destroy()` этот флаг не снимают. Без
  `synth.destroy(); synth.isLoaded = false;` играет прежний буфер: выбираешь
  «только мелодию», а звучат все четыре голоса. Проверяется отпечатком буфера.
- **Семплы abcjs грузит XMLHttpRequest'ом**, не `fetch` — для автономности
  перехватывается `XMLHttpRequest.prototype.open` с подменой на `blob:`.
  Имена файлов у семплов бемольные (`Db4`, не `Cs4`).
- **Подсветку класс `abcjs-note-playing` кладёт на группу без `abcjs-note`** —
  селектор из двух классов не срабатывает, нужен один плюс вложенные `path`.
- **Штатный `abcjs-audio.css` обязателен**, иначе кнопки плеера наезжают друг на друга.
- **Следующий куплет нельзя запускать прямо из `onFinished`** — он вызывается
  изнутри `finished()`, и `play()` застаёт контроллер на полпути; нужен `setTimeout`.
- **`%%barnumbers N` при включённом `wrap` работает как «каждый такт»**: шаг
  учитывается только без переносов. Номер «в начале строки», как в печатном
  сборнике, abcjs не умеет вовсе — лишние подписи снимаются по отрисованному SVG
  (`thinBarNumbers` в `page.tpl.html`): своего класса у номеров нет, но они
  выстроены по `y`, и в строке остаётся самый левый. Директиву в шапку ABC
  ставит `abcout.py`: без неё механизм прореживания есть, а прореживать нечего —
  номеров не рисуется вовсе.
- **Второй голос стана виден по перекрытию, а не по совпадению onset.** Под
  половиной с точкой в басу идёт восьмая пауза с нотами — её onset уже другой.
  Пока слои делились по равенству времени, пауза уезжала во второй слой и
  растягивалась до конца такта: на экране целотактовый прямоугольник, которого в
  PDF нет. Отсюда же правило: нота в конце слоя тянется до конца такта, пауза —
  ровно свою длительность, хвост добирается невидимой `x`-паузой.
- **Паузу на общем стане рисует только верхний голос.** В PDF целотактовая пауза
  одна на нотоносец, а голосов на нём два (S+A, T+B) — вторая нарисованная дала бы
  второй прямоугольник; у нижнего голоса пауза невидимая (`x`).
- Текст из PDF брать `get_text("words")` нельзя без фильтра: глифы Maestro
  приезжают вперемешку со слогами.

## Пакетный разбор: тринадцать сборников

`python3 checkall.py` печатает по строке на файл. Четыре колонки — приёмка:

- **расх** — такты, где сумма длительностей голоса не равна размеру. Проверка
  арифметики внутри такта: разбор либо сходится, либо нет.
- **перекр** — сколько раз соседние голоса поменялись местами по высоте
  (сопрано ниже альта, тенор ниже баса). Хоровая партитура так не пишется, и
  ноль расхождений в суммах о высотах не говорит ничего: перепутанные голоса
  видно либо этой проверкой, либо глазами по всем страницам.
- **ном** — совпадение с номерами тактов, напечатанными в PDF. Единственный
  эталон внутри самого файла, и единственная проверка на **число** тактов:
  пропущенная тактовая черта сливает два такта в один, и обе половины по
  отдельности сходятся по сумме длительностей. Нумеруют не все и не одно и то
  же — в 662 слева стоят номера **строк**, они опознаются по совпадению с
  порядковым номером системы и в эталон не идут.
- **неизв** — глифы нотного шрифта, которым не нашлось семантики. Инвентарь, а
  не ошибка: пока ноль, разбор видит всё, что в файле напечатано нотным
  шрифтом. Известное исключение — 752, где строка темпа («♩. = 60_64») набрана
  тем же подмножеством шрифта, что и ноты, и её буквы попадают в эту колонку.

Все четырнадцать файлов (тринадцать сборников плюс 093) дают ноль по первым
трём колонкам: 44 такта в 119, 30 в 1473, 28 в 1487 — вместе около 290 тактов.

## Сверка глазами: `proof.py`

Числовая приёмка ловит арифметику такта и число тактов, но молчит про высоты:
перепутанная нота даёт ту же сумму длительностей. Сверять высоты по тексту ABC
мучительно — надо держать в голове и порядок нот, и их номера, и вид такта в
PDF.

`python3 proof.py ../pdf/752.pdf 0 4` надписывает разбор поверх самой страницы:
над верхним станом — что распозналось у сопрано и альта, под нижним — у тенора
и баса, у каждой тактовой черты — сквозной номер такта. Глаз сравнивает подпись
с головкой прямо под ней. Длительность пишется рядом с высотой, потому что
ошибка в ней выглядит на странице так же безобидно, как верная нота: сумма
такта сойдётся, если ошиблись симметрично в двух местах.

## Находки на других сборниках

- **Допуски держать в долях межлинейного, а не в пунктах.** 752 набран мелко
  (4.02 pt против обычных 5.46) — на нём разъехалось всё сразу: штили не
  находили головок, тактовые черты множились. После перевода допусков в доли
  `staff["space"]` — 23 такта, ноль расхождений.
- **Гомофонная запись.** В 752 почти каждый штиль несёт две головки (сопрано и
  альт под одним штилем), а не два штиля рядом; divisi — единицы на всю песню.
  Голоса разводятся по головкам одного штиля, а не по совпадению времени.
- **Свой нотный шрифт вместо Maestro.** 664 набран шрифтом MSTT31c3c800
  (FontMatrix 1/2048): стан — глиф U+0004, штили — цепочки U+000C/U+000A, вязки —
  залитые параллелограммы. Разбор вынесен в `glyphstaff.py`, включается
  диспетчерски (`patch()`) и на векторных файлах не мешает.
- **Станы в систему объединяет вертикаль, а не чётность.** «Каждая пара подряд —
  система SATB» верно только для чисто хоровой партитуры: в 1487 куплет набран
  как «вокал + фортепиано» (три стана), в 119 — хор с фортепиано (четыре), а в
  1473 первые две системы одиночные, и пары собирались поперёк систем. Связывает
  станы любая вертикаль от верха одного до низа другого — начальная черта,
  скобка группировки, сквозная тактовая черта.
- **Вокал от аккомпанемента отделяет содержание, а не форма.** Три стана и
  больше — партию фортепиано печатают снизу и всегда на двух станах, значит
  нижняя пара фортепианная. Два стана значат разное: в хоровом сборнике это
  хор, а в партитуре с фортепиано — и хоровой припев (1487), и фортепианная
  интерлюдия (119), где хоровые станы не выписаны вовсе. Отличает их
  подтекстовка: под хором есть слоги, под интерлюдией нет.
- **Фортепиано в ABC не переносится.** Приёмка стоит на «сумма длительностей
  голоса в такте равна размеру», а фортепианная фактура этому правилу не
  поддаётся — ошибки в ней остались бы незамеченными, зато её такты нужны для
  сквозной нумерации: без них номер такта песни поедет на длину вступления.
- **Целую ноту проверять раньше половинной.** Головка у неё открытая, как у
  половинной, и по признаку «пустая головка» она читалась вдвое короче.
- **Части акколады лежат в шрифте-компаньоне.** В 1473 (Opus) верхняя половина
  скобки — код 0xB0 в OpusSpecialStd; пока он был не опознан, компаньон не
  признавался нотным шрифтом целиком, а вместе с ним из разбора выпадала точка
  длительности 0xAA из того же шрифта — и все ноты с точкой читались короче на
  треть.
- **Вольты печатают тремя вещами сразу** — двойной чертой, парой точек и скобкой
  над станом. По отдельности ни одну брать нельзя: двойная черта стоит и в конце
  песни, точки — те же глифы, что точки длительности, а скобка бывает без цифры.
  Скобку рисуют и справа налево (752), поэтому ножку ищем у обоих концов.
- **Номера вольты бывают списком**: «1.,2.,3.» → в ABC `|1,2,3`.
- **Метроном набран нотными глифами, а не текстом.** В 752 это «♩. = 60–64»:
  нота-единица, точка, знак равенства и цифры **отдельного курсивного набора**,
  не совпадающего с цифрами размера такта. Неизвестный код лучше вернуть как
  «не прочитан», чем угадать: ошибка в темпе выглядит как ошибка распознавания.
- **Характер исполнения («Выразительно») отсекается от заголовка сравнением с
  самим заголовком**, а не расстоянием до стана: в части сборников заголовок
  стоит вплотную к первой системе.
- **Подписи шапки переносятся как есть, вместе с местом на странице.** Слева от
  заголовка стоит то автор слов («Александр Рыжов» в 1473), то переводчик («Пер.
  И.С.П.» в 662), посередине — то эпиграф из Писания, то состав («для смешанного
  хора S.A.T.B. a cappella» в 752), справа — автор музыки или редактор
  гармонизации. Классификация по смыслу начала бы врать на первом же сборнике,
  поэтому строка остаётся строкой, а роль подписи передаётся выравниванием —
  в HTML это сетка из трёх колонок. Полей под них в ABC нет вовсе, так что
  подписи живут в `meta.json` рядом с заголовком, а не в самой записи нот.
- **Строки шапки собираются по высоте, а не по верхней кромке слова**: в
  эпиграфе 662 ссылка «Иоан.4:35» набрана мельче фразы, и строка распадалась
  надвое с перепутанным порядком слов.
- **Автор слов и автор музыки стоят на одной высоте** — слева и справа. Без
  разрыва по горизонтали они склеиваются в одну подпись и читаются как двойная
  фамилия («Александр Рыжов Маргарита Колываенко»).
- **Метроном и ключевые знаки приходят в текст страницы вместе со словами.**
  Коды у них из приватной области Unicode: по этому признаку они и отсеиваются —
  иначе «Выразительно» в 752 слипалось с «♩.=60–64» и переставало опознаваться
  как характер исполнения.
- **Динамика набрана нотным шрифтом, а не текстом.** Её долго считали
  отсутствующей, потому что искали среди слов: в Maestro «mp» — один глиф
  (0x50), а не пара букв, и в текст страницы он приезжает наравне с головками.
  В 119 так набраны `p`, `mp`, `mf`, `f`; в остальных тринадцати файлах
  динамики действительно нет — ни этими кодами, ни текстом (проверено по всем
  шрифтам каждого файла).
- **Оттенок относится к стану, а не к голосу.** В PDF он стоит над верхним
  станом и под нижним — по знаку на пару голосов; в ABC «знака на стан» нет,
  поэтому он вешается на верхний голос стана (S и T). Нижнему голосу знак не
  дублируется: два одинаковых «mf» друг под другом читаются как ошибка набора.
  Знак ищется рядом со **своим** станом: глифы системы приходят от всей
  страницы, и оттенок соседней системы с похожим `x` прилипал к первой попавшейся
  ноте. Порог — пять межлинейных, а не три: под станом знаку мешают штили и
  слова, и там он отодвинут дальше, чем над станом (в 119 — 3.7 против 2.2).
- **Ремарку ставят там, где есть место.** `rit.` в 119 лежит не над верхним
  станом, а между вокальным и фортепианным, внутри системы, — поиск только над
  станом его терял. Полосу можно расширить на всю систему потому, что список
  ремарок закрытый (`Fine`, `D.C.`, `rit.`, `a tempo`): слова песни в него не
  попадают, они по-русски. В этом же списке — русское «Припев»: это не термин
  исполнения, а указание строения, и в сборнике им помечают такт, с которого
  начинается общая для всех куплетов часть (1487, 655, 656, 662, 744, 093).
- **Спорную ремарку забирает нижняя система, а не ближняя.** Полоса поиска шире
  зазора между системами, и одна ремарка попадала сразу в две — в 656 «Припев»
  так удвоился. Расстояние тут обманывает: в 744 «Припев» лежит на 17 пунктов
  ниже предыдущей системы и на 30 выше своей. Решает смысл — ремарку печатают
  над той музыкой, к которой она относится.
- **Внутренние затакты бывают не только в начале песни.** В 1473 куплет
  кончается неполным тактом (4.5 из 6), а припев начат затактом (1.5) — по
  отдельности оба «не сходятся», вместе дают ровно размер. Пара ищется на
  границе систем: издатель разрывает раздел по строкам, и внутри строки такая
  пара означала бы ошибку разбора, а не вёрстку.
- **`%%score` в теле ABC abcjs игнорирует.** Скрыть пустые станы Тенор/Бас на
  строках, где вокал одностанный (1473, 1487), не получается: шапка
  `%%score {(S A) | (T B)}` фиксирована на всю песню, а смену состава по
  строкам abcjs не поддерживает ни через `%%score`, ни через `%%staves`.
  Остаётся косметическим ограничением.
- **Дефис переноса издатель опускает**, когда слоги и без него стоят впритык
  («к звез|дам» в 093). Зазор между словами всегда шире пробела, поэтому
  слипшиеся токены — один разорванный по нотам слог, а не два слова.
- **Столбик отсылок «2.Как скло–» под первой системой — не текст куплета**, а
  подсказка, с чего начнётся следующий. Признаков два, и порознь они не
  работают: концевое тире обязательно (у настоящей подтекстовки там слог или
  знак препинания), но одного его мало — тире издатель ставит и длинное (752), и
  обычным дефисом (974), а строка куплета тоже может кончиться переносом.
  Второе условие — номер куплета уже встречался выше. Плюс ограничение по длине:
  отсылка — два-три слога, не строка. Без него в 093, где куплеты пронумерованы
  в каждой системе, под правило уходил весь текст восьми куплетов, и от них
  оставалось «Свой свет да- * * * * * *».
- **Отсылку нельзя просто выбросить — она и есть начало куплета.** В 752 первые
  слоги куплетов 2–4 напечатаны только в этом столбике: сам куплет начинается со
  второго слова, и без переноса отсылки в начало строки получалось «ня- ет- ся
  ко- лос» вместо «Как скло- ня- ет- ся ко- лос». Слоги садятся на те же
  x-координаты, что у опорного куплета. Но бывает и напоминание, а не замена: в
  974 «2.По–» повторяет слог, который в куплете уже напечатан, — отличие видно
  по совпадению текста, и тогда отсылка отбрасывается.
- **Тональность посреди песни меняется, и ABC это умеет.** В 1473 на пятой
  системе печатается новый ключ — три диеза вместо четырёх бемолей, — а в шапке
  стоял только `K:Fm`, так что вся вторая половина читалась в старой
  тональности: `F` вместо `F#`, `G` вместо `G#`. Смена выводится
  внутристрочным полем `[K:F#m]` перед тактом, и своим — у каждого голоса:
  в ABC это поле действует до конца своего голоса. Набор знаков посреди строки
  отличается от случайного диеза при ноте тремя признаками сразу — знаков два и
  больше, они продублированы на обоих станах системы и стоят правее первой
  тактовой черты. По всем четырнадцати файлам смена ровно одна, ложных нет.
- **Тонику для минора считаем по басу, отбрасывая переходный такт.** Иначе лад
  берётся из такта, который уже ведёт в новую тональность: в 1473 шапка так
  съезжала с `Fm` на `Ab`. И сравнивать тонику с названием тональности можно
  только по ступени, без знака: при трёх диезах сама тоника диезная («fis»), и
  сравнение целиком с «F#m» не совпадало никогда — минор находился только у
  бемольных ключей.
- **Хвост куплета и общая строка припева стоят над одними нотами.** В 752 в
  такой системе бралась только одна строка, и у каждого из четырёх куплетов
  терялось по 18 слогов. Складываются обе, но слоги общей строки, попавшие в
  `x`-диапазон своей, отбрасываются: у последнего куплета бывает своя концовка
  припева, и сложение давало «не не у- у- гас.».
- **Скобка вольты — не стан из одной линии, а нижний скрипичный — не второй
  хоровой.** 974 набран как «мелодия + аккомпанемент»: длинная горизонталь
  вольты попадала в поиск станов, а пара станов «скрипичный + скрипичный»
  разбиралась как SATB. Разбор таких вёрсток вынесен в `staff974.py`, кодировка
  шрифтов без объявленного ToUnicode (664, 974) — в `glyphtext.py`: буквы и
  нотные знаки опознаются по контурам, найденная кодировка дописывается
  документу. Обе подмены диспетчерские и на остальных двенадцати файлах ничего
  не меняют — проверено побайтовым сравнением ABC с ними и без них.
- **Гармония набрана своим шрифтом — как динамика и метроном.** «B♭m» в
  OpusChordsStd — это три глифа: буква, бемоль и знак минора, каждый со своим
  кодом, поэтому в тексте страницы обозначение выглядит как «B¨‹» и по словам не
  ищется. Из четырнадцати сборников гармония выписана в двух (1473 и 974), зато
  полностью — 34 и 25 обозначений. Басовая нота с альтерацией приезжает двумя
  спанами (у знака свой кегль, и PDF рвёт строку на нём); склеиваются они по
  зазору — внутри обозначения это единицы пунктов, между соседними десятки, — но
  обходить страницу при этом надо по строкам: при сортировке по чистому `x`
  между половинками одного аккорда вклинивался аккорд соседней системы.
- **Немецкую нотацию распознаём по всему файлу, а не по знаку.** Там, где
  встречается «H», буква «B» означает си-бемоль, и в ABC её надо писать `Bb`.
  По отдельному «B» немецкое обозначение от английского не отличить, зато двух
  систем в одном сборнике не смешивают — признак берётся с целого файла.
  Вешается аккорд на верхний голос: в PDF он стоит над верхним станом, а
  «аккорда на систему» в ABC нет.
- **Голос выводится одной строкой ABC — переносы делает abcjs.** Разбивка по
  системам исходника прибила бы вёрстку к бумажному формату, а страница должна
  укладываться в любую ширину экрана. Цена — подтекстовка: строк `w:` столько,
  сколько куплетов, и общий припев повторяется в каждой (в 655 три одинаковых
  хвоста). Формально это верно — строка `w:` описывает один проход целиком, — но
  под нотами припева выглядит избыточно.
- **Нота под лигой распева слога не принимает.** Слог печатается под первой
  нотой лиги и поётся до её конца; если следующая нота возьмёт следующий слог,
  разъедется не одно место, а вся строка до конца системы — так в 656 и 661
  расползались целые куплеты. Тай — тот же случай при одинаковой высоте.
  Обратный перекос тоже бывает: часть изданий рисует лигу и там, где слог не
  тянется, поэтому при явной нехватке свободных нот раскладка возвращается ко
  всем нотам подряд — слипшиеся в один токен слова хуже лишней лиги.
- **Раскладка слогов по нотам — динамическое программирование, а не жадный
  проход.** Минимизируется суммарное смещение слога от своей ноты при условии,
  что порядок сохраняется. Пропуск ноты в середине строки штрафуется: без штрафа
  раскладка охотно роняла дырку, лишь бы подвинуть остаток строки на пункт ближе
  к своим нотам — в 093 так появлялись «*» посреди сплошного текста. Хвост
  системы, наоборот, бесплатен: строка куплета кончается там, где кончается её
  текст, а дальше идут ноты припева или проигрыш.
- **На одной ноте бывает несколько слогов — но только целых слов.** «к тро-ну»,
  «в дом»: безударный предлог или союз своей ноты не получает. Внутри слова так
  не поют, поэтому группа разрешена лишь там, где все слоги, кроме последнего,
  слово заканчивают, — иначе раскладка сливала «плод-ным» и роняла остаток
  строки на такт вперёд. Расстояния этот случай не решают: в 660 «в дом» и
  «дом От-» отличались по сумме смещений на треть пункта. Решает список
  безударных односложных слов — вещь языковая, а не геометрическая.
- **Слипшийся кусок с двумя гласными — это два слога.** Дефис между ними в PDF
  бывает нарисован линией, а не набран текстом («ли-ку-ю» в 119), либо слова
  напечатаны вплотную и пробела не осталось («бе-рем сно-пы» в 655,
  «пожнешь, что» в 658). Опереться не на что, кроме строения слога: гласная в
  нём ровно одна. Граница ставится так, чтобы первой части досталась одна
  согласная из двух и более, и ни одной, если согласная всего одна («ку-ю»);
  мягкий знак к следующему слогу не уходит. Знак препинания внутри куска решает
  сам за себя — там граница слов, и дефис не нужен. На четырнадцати файлах таких
  кусков ровно пять, и все требовали разреза; остаточная неточность — «бе-рем-
  сно-пы» в 655, где дефис лишний, потому что там кончилось слово.
- **Строки подтекстовки собираются по низу бокса, а не по верху.** Верх зависит
  от того, попалась ли в слог высокая буква, и внутри одной строки гуляет на
  пять с лишним пунктов — больше, чем зазор между куплетами. В 658 слог «мешь»
  так отделился от своей строки и пропал из куплета, оставив «при * ты мзду».
  Низ держится базовой линии: выносные вниз дают около двух пунктов при
  межстрочном интервале в двенадцать.
- **Строку припева отличает от хвоста куплета длина, а не начало.** В системе,
  где куплеты кончаются, хвосты («мой.», «вет?») стоят столбиком слева, а припев
  начинается правее — но левее середины, и по началу от хвоста не отличался: в
  744 он вставал третьей строкой столбца и сдвигал метки двух последних
  куплетов. Длина берётся относительно соседей: там, где номера напечатаны
  только у первой системы (656), все строки сплошные, и «длинная — значит
  припев» перепутало бы куплеты между собой.

- **Серп лиги приезжает разрезанным пополам.** В 664 половинки стоят встык
  (438.6–446.9 и 446.9–454.4, общая контрольная точка кривой), и порознь каждая
  накрывает две ноты вместо трёх, а левая ещё и не проходит проверку «шире своей
  высоты»: восемь дуг из восемнадцати оставались без голоса, и распев печатался
  без пометки. Склейка идёт **до** геометрического фильтра и только по стыку —
  между двумя настоящими лигами всегда видимый просвет, так что соседние дуги
  она не слипает: из четырнадцати сборников число лиг изменилось только у 664
  (10 → 24).
- **Нота под распевом помечается `_`, а не `*`.** Под лигой и после тая слог
  тянется с предыдущей ноты — abcjs рисует под такой нотой линию продления,
  ровно как чёрточка в печатном сборнике. Звёздочка значит другое: «слога нет
  вовсе» (проигрыш, вступление), и ставить её на распев значило бы выбросить
  сведения, которые у нас есть.
- **Дефис внутри бокса соседнего слова — это внутренний перенос.** В 119
  «ли-ку-ю» набрано так, что «кую,» приезжает одним токеном, а дефис между «ку»
  и «ю» — отдельным, с координатами внутри этого токена. Делить такой кусок всё
  равно приходится по гласным, и дефис после разреза приклеивался к последнему
  слогу: «ку- ю,-» вместо «ку- ю,».
- **Дефис переноса бывает длинным тире.** В 664 шрифт без `ToUnicode`, и контур
  дефиса опознан по ближайшему похожему знаку — шестьдесят штук. Тире как знак
  препинания так не стоит: оно отделено пробелами, а не приклеено к букве в
  конце слога. Короткое тире не трогаем — им кончаются строки-отсылок в 752, и
  по нему они и отличаются от подтекстовки.
- **Состав голосов считается по факту, а не по числу станов.** 974 — «мелодия с
  аккомпанементом», хоровых партий там нет: три стана из четырёх шли сплошной
  невидимой паузой и занимали половину страницы пустой нотной бумагой. Голос без
  единой ноты не выводится вовсе, скобки `%%score` ставятся только вокруг
  настоящей пары, подпись стана — только когда голосов несколько («Сопрано» у
  мелодии с аккомпанементом ещё и неправда), а страница прячет переключатель
  голосов: выбирать не из чего, и неработающие кнопки выглядели бы поломкой.
- **Нотный шрифт в полосе подтекстовки читается как кириллица.** Полоса поиска
  слов у вокала с фортепиано доходит до аккомпанемента, и в 119 весь он приезжал
  в куплеты: головка Maestro — голый байт `0xCF`, а `fontmap.cyr` читает старший
  байт как cp1251, то есть как букву «П». Получалось «П~П~Вер- ность Тво- я».
  Приватные коды (`U+F0xx`) отсекались и раньше, голый байт — нет, поэтому
  шрифт проверяется по имени: спан нотного шрифта словом быть не может.
  Ни сверка длительностей, ни проверка раскладки этого не ловят — такты сходятся,
  слоги стоят под нотами, мусор виден только глазами.
- **Кириллица без `ToUnicode` приезжает латиницей-двойником.** У курсивных
  шрифтов 664 буквы опознаны по контуру: «Припев» → «Hpuneв», «Перевод Д. А.
  Ясько» → «Hepeвoд Д. A. Яcькo». Замены двойников (`LOOKALIKE`) мало — «Н» и
  «П» в курсиве неразличимы, — поэтому ремарки и подписи шапки дотягиваются до
  закрытого словаря, если расходятся с ним на одну букву. Списки закрытые: запас
  «на одну букву» тем опаснее, чем короче слово, а фамилии чинить нечем.
  Инициал («Д. A.») правится отдельно — своей кириллицы в нём нет вовсе.
- **Ширину слова делит фактическая раскладка, а не длина исходного токена.** У
  слитно напечатанного слова при разрезе появляется дефис («знойный» →
  «зной-ный»), и раскладка на знак длиннее. Считая по исходной длине, последний
  слог вылезал правее конца слова и накрывал начало следующего: в 664 выходило
  «в~зной- ный- пол- день» — слово с дефисом посреди.
- **Номер вольты прячется под аккордом.** В 974 abcjs рисует буквенное
  обозначение там же, где номер вольты, и над скобкой видно «Em» вместо «1.».
  Это разметка вывода, а не разбор: в ABC стоят и `[1`, и `"Em"`.
- **Слог, напечатанный один раз на несколько куплетов, размножить нечем.** В 655
  «Со- бе-» в припеве стоит только на уровне куплета 2 и относится ко всем трём;
  у куплетов 1 и 3 на этом месте остаются два `*`. Достроить их можно было бы
  только догадкой о том, что припев у куплетов общий, — а он общий не всегда.

## Правки вывода поверх отрисованного SVG

Три вещи чинятся не разбором и не разметкой ABC, а кодом страницы, который
доводит уже готовый SVG. Причина общая: раскладка строк заранее неизвестна —
ширину решает экран, и до отрисовки не видно ни где будет перенос, ни сколько
тактов поместится.

- **Открывающая реприза на переносе строки** (`moveRepeatsToLineStart`). В модели
  abcjs тактовая черта принадлежит **концу** такта, поэтому `|:` перед первым
  тактом новой строки остаётся висеть в конце предыдущей — знак повтора стоит
  там, где повтор не начинается. Разметкой не лечится: `||:`, явный перенос и
  подбор `preferredMeasuresPerLine` дают тот же элемент в том же месте (в 655 на
  широком экране чистым выходил только один вариант — пять строк вместо трёх,
  то есть раскладка портится сильнее дефекта). Поэтому группа `|:` (четыре path:
  жирная, тонкая, две точки) копируется в начало следующей строки — в зазор
  между ключом и первой нотой, — а на старом месте остаётся обычная тонкая
  черта. Места там около 10 пунктов при ширине знака 14, поэтому копия сжимается
  по горизонтали; сжатие сильнее чем вдвое (`s < 0.45`) считается неудачей, и
  знак не переносится.

  **Копия не повторяет исходную геометрию, а подгоняется под стан назначения.**
  Первая версия просто сдвигала клон по вертикали — и знак «ломался»: у нижнего
  стана вертикаль репризы тянется через **всю систему** (в 655 это 160 пунктов
  против 176 в другой строке), потому что она же соединяет станы, а расстояние
  между станами у строк разное — оно зависит от числа подписанных строк текста.
  Поэтому вертикали растягиваются по высоте черты, уже нарисованной в новой
  строке для **этого же** стана, а точки повтора просто переезжают в свой стан.
  Линия черты ищется как первый `path` группы: первым ребёнком там лежит
  `<text>` номера такта, и по нему знак садился выше стана и вдвое короче
  нужного. Сам номер такта в копию не едет — он принадлежит старому месту.

  Левый край считается по ключу **своего голоса** (`.abcjs-clef.abcjs-lN.abcjs-vM`
  плюс знаки при ключе), а не по первому ключу системы: у станов ключи разные —
  скрипичный и басовый, — и по чужому знак садился на ноты или левее ключа.
  Стан назначения берётся по индексу из модели, а не по близости: станы стоят
  вплотную, и «ближайший» у нижнего голоса легко оказывается верхним.
  Сторож — проверка по всем ширинам, на которых перенос вообще случается
  (в 655 их девятнадцать в диапазоне 380–1500 px): у каждой копии вертикаль
  обязана доходить до низа своего стана, точки — лежать внутри него, а сам знак
  стоять правее ключа.
- **Номера тактов — только в начале строки** (`thinBarNumbers`). При включённом
  `wrap` abcjs подписывает каждый такт и шаг `%%barnumbers N` игнорирует. Лишние
  подписи гасятся по отрисованному. **Отбор идёт по классу `abcjs-bar-number`**
  (появляется от `add_classes: true`), а не по признаку «текст из одних цифр»:
  прежнее правило заодно гасило номера вольт — они тоже цифры и стоят далеко от
  края строки. Регрессия жила незамеченной, пока классы не понадобились для
  переноса репризы.
- **Патчить сам abcjs нельзя.** Библиотека вшита в каждый HTML минифицированным
  бандлом: правка потерялась бы при обновлении и лежала бы в четырнадцати копиях.
  Дешевле доводить результат своим кодом.

## Одна пауза на два голоса стана

В печатном сборнике, когда обе партии стана молчат одновременно, нарисован
**один** знак паузы посреди стана — так набран такт 24 в 1487. ABC описывает
голоса порознь, и две записанные паузы abcjs честно рисует друг над другом:
верхнюю над станом, нижнюю под ним.

- **Дубль гасит генератор** (`merge_stave_rests` в `abcout.py`): нижнему голосу
  пауза заменяется на невидимую (`x`). Гасится именно нижний — слова печатаются
  под верхним голосом стана, и его события остаются теми, к которым привязан
  текст. Совпадение требуется точное, и момент и длительность: паузы разной
  длины в оригинале выписаны обе, объединять их значило бы потерять голос.
- **Оставшийся знак возвращает на место страница** (`centerLoneRests`). abcjs
  разводит паузы по числу голосов в стане, а не по направлению штилей, поэтому
  единственная пауза всё равно висит за станом. Смещение постоянное — ровно два
  межлинейных интервала при любой длительности (проверено на `z1`…`z12`), — и
  знак возвращается сдвигом, а не центрированием по рамке: у половинной и целой
  паузы своя посадка относительно линий.
- **Разметкой ABC не лечится**: ни `stem=`, ни `[I:stem auto]`, ни отсутствие
  `stem` в заголовке голоса позицию паузы не меняют.
- Паузу, у партнёра которой в это время **ноты**, никто не трогает: разводить её
  правильно. В 1487 из десяти пауз сдвинуто восемь.

## Текст: все куплеты подстрочно или один выбранный

В PDF под нотами напечатаны строки всех куплетов, одна под другой. Страница так
и показывает по умолчанию (`verse = 0` в `abcFor` оставляет все строки `w:`), а
кнопки «Текст: все куплеты / выбранный» переключают на строку одного куплета —
это выбор «показать только то, что поётся сейчас», а не вид по умолчанию.

Переключение куплета при подстрочном тексте **не перерисовывает партитуру**
(ранний выход по `drawnLyrics`): на экране и так все куплеты, перерисовка ничего
не изменила бы, зато сбивала бы подсветку посреди пения. Группа кнопок скрыта,
когда куплет один.

## Клик по ноте — перемотка

Клик по ноте переносит воспроизведение на неё: на ходу звук продолжается с этого
места, на паузе переезжают позиция, подсветка и курсор.

- **Время берётся у abcjs** (`currentTrackMilliseconds` на элементе модели,
  который приходит в `clickListener`), а не считается по темпу: своя арифметика
  разошлась бы на повторах, вольтах и смене куплета.
- **У ноты внутри повтора значений несколько** — она звучит дважды, и берётся
  ближайшее к текущей позиции. Иначе клик по припеву во втором проходе
  отбрасывал бы плеер в первый.
- **Первый клик сам заряжает звук.** Он собирается лениво, до этого у нот нет
  времени вовсе, и клик раньше просто ничего не делал. Но клик — тот самый жест
  пользователя, которого не хватало для AudioContext: `setUpAudio(true)`
  вызывается прямо из обработчика, под флагом от повторного входа.
- На паузе `seek` только двигает позицию и ничем этого не показывает, поэтому
  ноту подсвечиваем и ставим на неё курсор вручную.

## Аккомпанемент по буквенным аккордам слышно там, где нот нет

В 1473 в первых восьми тактах слышны басы, которых на нотоносце нет. Разбор тут
ни при чём: в PDF это одноголосный запев, у альта, тенора и баса там `x12`
(невидимые паузы, они не звучат). Звучит **пятый трек**, который abcjs добавляет
сам по буквенным обозначениям `"Fm"`, `"B♭m"` — бас плюс созвучие; в собранном
буфере у него 1023 ноты и старт с нуля, тогда как голоса вступают с 11.625.

Отключать аккомпанемент насовсем жалко (в запеве осталась бы голая мелодия),
поэтому на панели появился переключатель «Аккорды: играть / не играть»
(`chordsOff` в параметрах `setTune`). По умолчанию играет — гармония помогает; в
песне без буквенных обозначений группа кнопок скрыта, чтобы не показывать выбор,
которого нет.

## Объёмы для всего песенника (1565 песен)

ABC-запись песни — единицы килобайт, весь песенник ≈ 5–8 МБ текста. Семплы от
песни не зависят: один тембр ≈ 1.2 МБ mp3 (1.6 МБ в base64), то есть их грузят
один раз на всё приложение, а не на песню.

## Куда это едет: ноты в самом песеннике

Исследование — не самоцель. Цель — **фаза 9** дорожной карты приложения
(`docs/roadmap.md`, пока заготовка): ноты и семплы приезжают на устройство вместе
с текстами песен и рендерятся внутри PWA из ABC, **одним движком на все 1565
песен**, который дорабатывается под нужды приложения.

Отсюда четыре требования к решениям, принимаемым здесь и сейчас:

- **Партитура хранится как ABC**, а не как картинка и не как готовый SVG: только
  текст переживает транспонирование, смену состава голосов и правку данных.
- **Движок один и не патченный.** В автономных страницах abcjs вшит в каждый файл
  (сам движок ≈ 512 КБ, остальное — семплы), но в приложении он будет
  npm-зависимостью с ленивой загрузкой. Поэтому любая доводка вывода делается
  **своим кодом поверх отрисованного SVG** — иначе она потеряется при первом же
  обновлении библиотеки и её пришлось бы держать в четырнадцати копиях.
- **Семплы общие на приложение**, а не на песню: 2.1 МБ фортепиано, 2.3 МБ хор, от
  партитуры не зависят. Всё, что мы прибиваем к отдельной странице, в PWA придётся
  переделывать.
- **Транспонирование нот и аккордов синхронизировано** — решено. Значение одно на
  песню (`songSettings.transpose` из фазы 5, в полутонах): сдвинул на нотах —
  сдвинулись аккорды над текстом, и наоборот. Отсюда два следствия для здешнего
  кода: сдвиг применяется **при отрисовке** (`visualTranspose` + `midiTranspose`),
  а ABC хранится в исходной тональности — иначе исходник портится необратимо; и
  диапазон надо привести к −6…+5, как в дорожной карте, вместо нынешнего
  `KEY_LIMIT = 6`: по кругу ±6 — одна и та же тональность с двух сторон, лишний
  дубль в интерфейсе.

Что именно переедет в приложение из здешнего кода: перенос открывающей репризы,
номера тактов только в начале строки, клик-перемотка, переключатель аккордового
аккомпанемента. Сам разбор PDF в приложение не едет — это инструмент разработчика.

## Что осталось нерешённым

Бесшовное переключение тембра и состава голосов на ходу (сейчас звук
пересобирается с остановкой). Разведано: нужен свой плеер поверх `CreateSynth` с
кэшем прогретых буферов и `seek(позиция, "seconds")` — цена ≈ 15 МБ памяти на
вариант и отказ от штатной панели. Отложено как неприоритетное.
